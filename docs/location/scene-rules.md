# 场景创建规则（V1）

## 1. 重名：允许

同一个名称可以创建多个场景。例如两个校区都有“图书馆”，或“家”和“父母家”都叫“家”。

原因：

- 场景的身份是 `sceneId`，名称只是展示和 AI 匹配用的文本，不是主键。
- `SceneCatalog.resolveByName()` 遇到多个同名结果会返回 `AMBIGUOUS`，不会随便选一个。
- AI 流程会把多个候选交给用户确认，这比强行禁止重名更符合真实地点。

UI 建议：创建时检测到同名，给一个**提醒**而不是报错：

> 已存在同名场景“图书馆”，保存后使用该名称时需要选择具体地点。仍要保存吗？

保存后不要自动合并，也不要覆盖旧场景。

## 2. 半径：100–5000 米，边界值可用

`SceneCatalog` 现在统一校验：

| 规则 | 值 |
| --- | --- |
| 最小半径 | 100 米（含） |
| 最大半径 | 5000 米（含） |
| 非法值 | 非有限数、`< 100`、`> 5000` |

超出范围统一抛 `LOCATION_INVALID_RADIUS`。

为什么不是“大于 0 即可”：

- GNSS 围栏只在室外有效，普通定位漂移可能几十米。
- 半径太小时，用户在边界附近会反复进出，产生重复触发。
- 半径太大时，“到达该地点”失去意义，例如把半个城市都算作“实验室”。

`100` 和 `5000` 是产品边界，不是系统 API 的硬限制；以后要放开，修改 `SCENE_MIN_RADIUS_METERS` / `SCENE_MAX_RADIUS_METERS` 即可。UI 应直接复用这两个常量，避免前后端提示不一致。

## 3. 场景数量：不设业务上限

V1 不限制用户创建多少个场景。原因是：

- 场景本身只存名称和坐标，不占系统围栏。
- 真正有限制的是**同时激活的地点提醒**：每个激活的地点提醒会注册一个 GNSS 围栏。
- OpenHarmony 当前实现中，单个应用最多约 **100 个 GNSS 围栏**，系统总量约 1000 个。HarmonyOS 商用版本可能不同，但不应按“无限”设计。

因此：

- 场景数：不拦截；UI 可以在超过 50 个时提示“场景较多，建议整理”，但不阻止。
- 激活的地点提醒数：接近 100 时要有明确提示；超过平台上限时，`addGnssGeofence` 会失败，最终表现为 `LOCATION_FENCE_REGISTRATION_FAILED`。

不要把“场景数量上限”和“围栏数量上限”混为一谈：100 个场景不一定有问题，100 个**同时激活的地点提醒**才会撞到系统上限。

## 4. 预置开发场景：不要放进正式数据

不建议在正式版本里自动创建“实验室”“宿舍”等示例场景，原因：

- 示例坐标是假的，AI 可能把用户说的“实验室”解析到错误地点。
- 用户会误以为这些是真实数据，删除时也会困惑。
- 测试已经通过 `MemoryTextStorage` 构造临时场景，不需要污染正式存储。

如果需要演示或真机验证：

- 只在开发模式提供“加载演示场景”按钮，并明确标注“演示数据”；
- 或者由测试代码临时创建，不写入用户正式存储；
- 不要把演示场景硬编码进 `SceneCatalog` 的初始化流程。

## 5. 落地的代码与错误码

- 校验和常量：[SceneCatalog.ets](entry/src/main/ets/location/scene/SceneCatalog.ets#L18-L36)
- 重名说明：[SceneCatalog.ets](entry/src/main/ets/location/scene/SceneCatalog.ets#L94-L101)
- 半径边界测试：[SceneCatalog.test.ets](entry/src/test/location/SceneCatalog.test.ets#L57-L70)

UI 需要处理的场景错误：

| 错误码 | 含义 | 可重试 |
| --- | --- | --- |
| `SCENE_INVALID_NAME` | 名称为空或超过 100 字 | 修改后可重试 |
| `LOCATION_INVALID_COORDINATES` | 经纬度非法 | 修改后可重试 |
| `LOCATION_INVALID_RADIUS` | 半径不在 100–5000 米 | 修改后可重试 |
| `SCENE_INVALID_ID_OR_CLOCK` | 内部 ID/时间异常 | 通常不可由用户修复 |
| `SCENE_STORAGE_INVALID` | 本地存储损坏 | 不可重试，需要恢复数据 |
| `SCENE_IN_USE` | 场景被提醒引用或正在注册 | 先删除/修改相关提醒 |
| `SCENE_NOT_FOUND` | 场景不存在 | 刷新列表后重试 |

## 6. 数据兼容提醒

半径校验也会作用于已保存数据。如果旧版本存过 `<100` 或 `>5000` 米的数据，新版本读取时会报 `LOCATION_INVALID_RADIUS`，而不是悄悄修正。当前没有正式用户数据，因此不做迁移；如果发布前已有测试数据，清空场景存储即可。
