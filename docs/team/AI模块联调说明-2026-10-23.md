# AI 模块联调说明

## 当前可用能力

AI 模块已提供与供应商解耦的 `AIService`、严格 JSON 解析、字段与时间校验、地点名解析、统一创建输入映射。当前使用 `FakeAIModelProvider`，只返回预置样例，不具备真实自然语言推理能力。

本轮新增 `entry/src/test/AIWorkflowIntegration.test.ets`，连接真实的 `DefaultAIService`、`ReminderService`、`InMemoryReminderRepository` 和 `TriggerCoordinator`。时间、地点及通知采用测试替身。此验证不代表 `develop` 上的正式 UI/系统能力链路或真机验收已经完成。

本轮验证：全量测试报告为 `Tests run: 79, Failure: 0, Error: 0, Pass: 79, Ignore: 0`，debug `assembleHap` 成功，产物未签名。使用当前工程配置构建：`compatibleSdkVersion` 为 `6.1.1(24)`，`targetSdkVersion` 为 `26.0.0`；该结果不等于在 API 24 真机上完成了运行验证。

## 页面接入顺序

1. 调用 `AIService.parseReminder(text, context)`，其中 `context.now` 是调用时刻的 Epoch 毫秒；时区与语言可分别使用 `Asia/Shanghai`、`zh-CN`。
2. 根据 `status` 展示结果：`READY` 展示 `draft` 供用户确认，`NEEDS_CONFIRMATION` 提示补充或纠正字段，`FAILED` 展示失败并按 `retryable` 决定能否重试。
3. 用户确认前不调用创建服务。解析本身不保存提醒，也不注册任何触发器。
4. 用户确认后调用 `ReminderService.create(draft)`，再次检查 `success`。解析时合法的时间，在等待用户确认后可能已经过期，创建服务会重新校验并拒绝。
5. 创建成功后用返回的 `Reminder` 更新页面。不要由页面生成 id、修改状态或直接操作仓储。
6. 时间和地点适配器把条件事件交给共享的 `TriggerCoordinator`。通知成功只转为 `TRIGGERED`，用户主动完成才调用 `ReminderService.complete`。

## 本轮覆盖的联调用例

- READY 解析无副作用，用户确认后才注册触发器并保存。
- TIME 创建、到时通知、重复事件去重、用户完成。
- LOCATION 地点名解析到稳定 sceneId，查询当前位置后通知。
- BOTH 不保留过早的历史进入事件，时间与当前地点同时满足才通知。
- 用户确认时草稿已过期，拒绝创建且不注册触发器。
- 地点无法解析及 AI JSON 损坏，不产生正式提醒。
- BOTH 地点注册失败，补偿已注册的时间条件且不留下正式记录。
- 通知失败保留 ACTIVE，下一次事件可重试，成功后重复事件不再通知。

## 真实 AI 接入前的准备

由组长确认服务商、模型、接入端点及是否使用后端代理。优先通过后端代理保管供应商密钥；把密钥排除出 Git 只能防止源码泄露，不能保护打包进客户端的长期密钥。

不要把 API Key、Secret、Token 发送到群、写入示例或提交到仓库。当前不要求提供密钥，也不新增含凭证的配置文件。

正式 Provider 应保持现有 `AIModelProvider` 签名，输出内部严格结构：

```json
{
  "content": "带电脑",
  "triggerType": "BOTH",
  "triggerTime": 1799992800000,
  "sceneName": "实验室",
  "ambiguous": false
}
```

以上时间只展示毫秒字段格式，不表示某一条自然语言的正确解析。五个键必须齐全，不适用的时间/地点字段返回 null；不附带 Markdown 或额外字段。模型不确定时返回 ambiguous=true，不能猜测后直接创建。

按照已确认的 Foundation Design 第 14 节，应先在 develop 验证 UI、正式时间/地点端口和通知的完整链路，再启用真实 Provider。尚未完成的现场验证包括权限、后台回调、真机围栏、系统通知和进程重启恢复；这部分需要两位模块负责人配合。
