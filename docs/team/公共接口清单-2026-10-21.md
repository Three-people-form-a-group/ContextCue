# ContextCue 公共接口文件清单（阶段五冻结版）

适用分支：`feature-ui`、`feature-location`、`feature-ai`。以下文件是三人协作的共同边界，不能在各自功能分支上随意改签名；确需修改时先在群里说明影响，由组长在公共分支统一合并。

## 一、统一数据模型

1. `entry/src/main/ets/model/ReminderEnums.ets`
   - `TriggerType`：`TIME`、`LOCATION`、`BOTH`。
   - `ReminderSource`：`MANUAL`、`AI`。
   - `ReminderStatus`：`ACTIVE`、`TRIGGERED`、`COMPLETED`、`DISABLED`。
   - `LocationTriggerMode`：V1 正式支持 `ENTER`；`EXIT` 仅预留，当前创建时会被拒绝。

2. `entry/src/main/ets/model/Reminder.ets`
   - 全项目唯一的提醒实体。UI、AI、时间、地点和通知模块不得另建不兼容的 Reminder 格式。
   - 时间戳统一使用 Unix Epoch 毫秒。

3. `entry/src/main/ets/model/CreateReminderInput.ets`
   - 手动创建和 AI 创建共用的服务输入。
   - UI 手动创建时设置 `source: ReminderSource.MANUAL`；AI 结果固定为 `ReminderSource.AI`。

4. `entry/src/main/ets/model/Scene.ets`
   - 跨模块共享的场景基础结构。地点模块内部专用字段应放到 `location/model/**`，不要扩充到这里。

5. `entry/src/main/ets/model/OperationResult.ets`
   - 公共服务返回格式：`OperationResult<T>` 和 `OperationError`。
   - 调用方必须先判断 `success`；失败时读取 `error.code`、`message`、`field`、`retryable`。

6. `entry/src/main/ets/model/ReminderModelRules.ets`
   - `validateCreateReminderInput(input, now)`：统一创建校验。
   - `canTransitionReminderStatus(current, next)`：统一状态转换规则。
   - 页面和适配器不要复制一套不同的业务校验；最终以 `ReminderService` 的校验结果为准。

## 二、提醒数据与业务入口

7. `entry/src/main/ets/repository/ReminderRepository.ets`
   - 仓储契约：`save`、`findById`、`findAll`、`deleteById`。
   - UI、时间模块、地点模块和协调器都不能直接使用仓储修改提醒状态，只能调用 `ReminderService`。

8. `entry/src/main/ets/service/ReminderService.ets`
   - 页面可调用：`create`、`findById`、`findAll`、`enable`、`disable`、`complete`、`update`、`delete`。
   - 协调器调用：`processActiveTrigger`（在同一提醒的服务串行区内重新确认并完成“通知后更新状态”）；底层状态入口为 `markTriggered`；清理失败恢复调用为 `retryTriggerCleanup`。其他模块不要直接调用协调器专用入口。
   - `processActiveTrigger` 的回调处于同一提醒的串行区内，回调和通知适配器都不能再等待该 `reminder.id` 的 `update`、`disable`、`complete`、`delete`、`markTriggered` 或另一次 `processActiveTrigger`，否则会形成自等待。
   - 构造参数依次为 `ReminderRepository`、`TimeTriggerPort`、`LocationTriggerPort`、时钟函数、ID 生成函数。已由 `app/AppServices.ets` 集中组装；页面使用 `app/AppServiceRegistry.ets` 的 `getAppServices().reminderService`，当前启动入口选用开发适配。
   - 页面不能自行写 `id`、`status`、`createdAt`、`triggeredAt` 或 `completedAt`。

## 三、时间、地点、通知和触发协调接口

9. `entry/src/main/ets/reminder/contract/TimeTriggerPort.ets`
   - 罗鸿程负责正式实现。
   - `schedule(reminder)`：为 TIME/BOTH 注册时间条件。
   - `cancel(reminderId)`：取消时间条件。
   - 时间到达时不直接发最终通知，而是向 `TriggerEventSink` 上报 TIME 条件事件。

10. `entry/src/main/ets/reminder/contract/LocationTriggerPort.ets`
    - 兰铮负责正式实现。
    - `register(reminder)`、`unregister(reminderId)`：注册/移除 LOCATION/BOTH 地点条件。
    - `isInsideScene(sceneId)`：查询当前位置是否位于目标场景，供 LOCATION/BOTH 最终判断使用。
    - 地点命中时不直接发最终通知，而是向 `TriggerEventSink` 上报 LOCATION 条件事件。

11. `entry/src/main/ets/reminder/contract/SceneResolver.ets`
    - 兰铮负责正式实现，AI 模块只依赖此接口。
    - `resolveByName(sceneName)` 返回 `RESOLVED`、`AMBIGUOUS` 或 `NOT_FOUND`；只有唯一匹配才能自动得到 `sceneId`。

12. `entry/src/main/ets/reminder/contract/TriggerConditionEvent.ets`
    - 条件事件统一结构：`reminderId`、`condition`、`satisfied`、`occurredAt`。
    - `condition` 只能为 `TIME` 或 `LOCATION`；`occurredAt` 使用 Unix Epoch 毫秒。

13. `entry/src/main/ets/reminder/contract/TriggerEventSink.ets`
    - 时间和地点适配器共同依赖的事件入口：`onConditionChanged(event)`。
    - 正式集成时注入的实现是 `TriggerCoordinator`。

14. `entry/src/main/ets/reminder/contract/ReminderNotificationPort.ets`
    - 罗鸿程负责正式 HarmonyOS Notification 实现。
    - `notify(reminder)` 只负责展示最终通知；失败时必须拒绝 Promise，不能假装成功。
    - 应尽量用 `reminder.id` 作为稳定且幂等的通知标识：如果通知已经成功但 TRIGGERED 状态保存失败，同进程重试或重启后重试都可能再次调用 `notify`。

15. `entry/src/main/ets/reminder/TriggerCoordinator.ets`
    - 组长维护的公共协调实现，同时实现 `TriggerEventSink`。
    - 构造参数：`ReminderService`、`LocationTriggerPort`、`ReminderNotificationPort`、时钟函数。
    - 应在应用组合入口只创建并共享一个协调器实例；即使服务层会串行最终提交，也不要让各适配器各自创建协调器。
    - TIME、LOCATION、BOTH 都必须经过这里；BOTH 固定为“时间已到且当前位置在目标 Scene”的 AND 语义。
    - 顺序固定为：判断条件 → 在 `processActiveTrigger` 串行区内执行 `notify` → 通知成功后由服务内部完成 ACTIVE → TRIGGERED。任何适配器不得绕过此流程直接把提醒标为 TRIGGERED。

## 四、AI 对页面公开的接口

16. `entry/src/main/ets/ai/contract/AIService.ets`
    - 页面只依赖 `AIService.parseReminder(text, context)`，不要直接调用具体模型供应商。
    - `AIParseContext` 必须提供当前 Epoch 毫秒、时区和语言地区。

17. `entry/src/main/ets/ai/model/AIParseResult.ets`
    - `READY`：`draft` 可交给用户确认，确认后再调用 `ReminderService.create`。
    - `NEEDS_CONFIRMATION`：信息不确定或字段有问题，必须让用户确认，不能擅自创建。
    - `FAILED`：网络、供应商、解析基础设施等失败；结合 `issues[].retryable` 决定是否允许重试。

以下文件属于 AI 模块内部边界，不要求其他两位成员直接调用：`AIModelProvider.ets`、`AIParsedReminder.ets`、`AIResponseParser.ets`、`AIParseValidator.ets`、`ReminderMapper.ets`、`FakeAIModelProvider.ets`、`DefaultAIService.ets`。真实 AI Provider 和密钥配置尚未接入，任何 Key、Token、Secret 都不能写入源码。

## 五、两位成员的接入规则

### 罗鸿程（UI、时间、通知）

- 页面通过 `AIService` 和 `ReminderService` 工作，不直接访问 `ReminderRepository`。
- 实现 `TimeTriggerPort` 与 `ReminderNotificationPort`。
- 时间系统能力触发后，构造 `TriggerConditionEvent` 并调用 `TriggerEventSink.onConditionChanged`，不要直接发送最终提醒通知。

### 兰铮（地点、Scene、地理围栏）

- 实现 `LocationTriggerPort` 与 `SceneResolver`，Scene 正式仓储和管理留在 `location/**`。
- 围栏/地点条件触发后，构造 `TriggerConditionEvent` 并调用 `TriggerEventSink.onConditionChanged`，不要直接发送最终提醒通知或修改 Reminder 状态。
- V1 只实现 ENTER；不要把预留的 EXIT 枚举当作已支持功能。

## 六、公共文件协作规则

- 上述 17 个文件以及 `EntryAbility.ets`、`module.json5`、`main_pages.json`、根/entry 构建配置、`oh-package-lock.json5` 都属于公共或高冲突文件。
- 其他成员如需改公共签名，应先说明“改哪个文件、为什么、影响谁”。
- 各自的正式实现放在分工目录：罗鸿程使用 `pages/**`、`components/**`、`reminder/time/**`、`reminder/notification/**`；兰铮使用 `location/**`。
- 当前 `InMemoryReminderRepository` 只用于开发和验证，应用重启后数据不会保留，不能当作最终持久化实现。
- 组长在 `app/AppBootstrap.ets` 集中选择正式依赖；`EntryAbility.ets` 负责启动初始化。两个入口文件均避免三人同时编辑。

## 八、2026-11-28 增量（集成轮冻结边界更新）

以下为 11 月集成轮的三处公共边界增量，均已三人知悉，并以官方测试套件（204 项）锁定：

1. `model/OperationResult.ets`：新增可选字段 `warnings?: OperationError[]`。
   - 语义：**创建与投递分离**——业务已保存但触发投递未完全生效。`success === true` 时也可能携带 warnings；调用方（页面）应把 warnings 的 `message` 渲染为非阻断提示，不得当作失败处理。
   - 现有 `error` 语义不变；忽略 warnings 的旧调用方完全兼容。

2. `model/ReminderEnums.ets`：`ReminderSource` 新增 `TIMETABLE`（课表生成的提醒）。
   - 冻结文件增量改动，经使用确认追认；消费者已审计（AI×3、MANUAL×4、TIMETABLE×2），无遗漏分支。

3. `service/ReminderService.ets` 语义更新（方法签名不变）：
   - `create / update / enable`：触发条件注册失败不再回滚业务保存，改为 `success: true` + `warnings`。时间端口失败映射稳定码 `TIME_SCHEDULE_FAILED`；地点失败沿用稳定码（`LOCATION_PERMISSION_DENIED` 等）。
   - 仓储保存失败仍回滚并补偿注册（语义不变）。
   - `ReminderModelRules.ets`：过去时间不再拒绝创建（保存为 ACTIVE 逾期待办）；允许 `COMPLETED → ACTIVE`（撤销完成，撤销时清空 triggeredAt/completedAt）。

其余公共文件签名无变化。投递恢复机制（回前台对账）见 [服务组装与页面接入说明](服务组装与页面接入说明-2026-10-25.md) 第 7 节；完整决策记录见《语义决策台账-2026-11-28.md》。
